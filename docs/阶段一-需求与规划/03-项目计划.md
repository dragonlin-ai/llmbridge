## 一、项目概述

### 1.1 项目目标

- **目标一**：实现「输入文本 → 自动判定目标模型 → 完成转发」闭环，路由判定准确率 ≥ 85%。
- **目标二**：路由决策额外延迟 ≤ 800ms（P95），且先于首个 token 完成。
- **目标三**：失败兜底率 100%，对外不返回 5xx。
- **目标四**：控制台 P0 页面全部可用，路由策略调整零代码、零重启。
- **目标五**：对外提供 OpenAI 兼容协议，业务方零改造接入。

### 1.2 项目范围

**包含内容**
- 统一接入层（`/v1/chat/completions`，非流式 + SSE 流式）
- 三层路由决策引擎（L1 规则短路 / L2 Jev 判定 / L3 组合选型与兜底降级）
- 执行层 Adapter 池（OpenAI 协议 / Anthropic 协议 / 本地 vLLM）
- 控制台 9 个页面
- 可观测性（Trace、Jev 判定概率分布、降级原因）+ 成本核算
- 部署物料（Docker Compose + Nginx 配置）

**不包含内容**
- 多租户隔离与计费账单（V2.0）
- 规则灰度与 A/B 实验（V2.0）
- L2 语义召回（embedding 近邻检索）—— 2026-09-21 决策移出方案，降为 V2 可选优化
- 决策样本管理页面与评测看板页面的完整实现（V1.1）
- 移动端适配
- 模型微调与托管

### 1.3 项目交付物

- **阶段一**：需求规格说明书、前端UI设计说明书、项目计划、验收标准、风险清单

- **阶段四**：测试计划、测试用例、缺陷报告、测试报告、质量评估报告
- **阶段五**：部署包（`deploy/`）、部署文档、发布说明、用户手册、运维手册
- **阶段六**：运维报告、问题分析报告、迭代计划、优化建议

## 六、进度风险与应对

| 风险点 | 触发信号 | 应对措施 |

| 路由准确率不达标（< 85%） | 阶段四评测结果低于阈值 | 细化并互斥化 `task_type` 枚举、优化 Jev `criteria` 描述、扩充 `eval_case` 评测集、必要时拆分辅助判定问题 |
