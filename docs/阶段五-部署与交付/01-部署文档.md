## 一、部署架构

```
客户端 ──▶ Nginx :80/:443
            ├── /            ──▶ admin-web/dist（静态）
            └── /v1/, /admin ──▶ gunicorn -k uvicorn.workers.UvicornWorker -w 4 -b 127.0.0.1:8000

                     ┌───────────────┼────────────────┐
```

## 三、部署步骤（Docker Compose，推荐）

> ```bash

> ```
>
> **国内网络（GitHub 不可达）**：改走 §3.6 的容器库形态，一条 `docker run` 装完，
> 全程不访问 GitHub：
>
> ```bash
> docker run --rm --entrypoint cat \
>   registry.cn-hangzhou.aliyuncs.com/winyeahs/llmbridge-api:1.0.0 \
>   /opt/llmbridge/deploy/docker-deploy.sh | bash -s -- --image
> ```
>
> 本节保留手工步骤，用于理解脚本做了什么或在脚本不适用时照着做。

### 3.1 前置

```bash
git clone <repo> && cd llmbridge
cp .env.example .env
# 必改项：JWT_SECRET、ENCRYPTION_MASTER_KEY（openssl rand -base64 32）、
#         POSTGRES_PASSWORD、JUDGE_PROVIDER（默认 mock，出境决策见安全方案 §3）
```

### 3.2 docker-compose.yml（交付物，位于 deploy/）

> **实际交付文件为 [`deploy/docker-compose.yml`](../../deploy/docker-compose.yml)，以它为准。**
> 下面这段是设计期的示意，与交付文件已有差异（交付文件另含显式 `networks`、
> db/redis 健康检查重试次数、`POSTGRES_PASSWORD` 必填校验等），保留在此仅作架构说明。

```yaml
services:
  api:
    build: ..
    restart: unless-stopped
    env_file: ../.env
    environment: [ "DATABASE_URL=postgresql+psycopg://llmbridge:${POSTGRES_PASSWORD}@db:5432/llmbridge" ]
    depends_on:
      db:    { condition: service_healthy }
      redis: { condition: service_healthy }
    command: >
      sh -c "llmbridge-seed &&
             gunicorn app.main:app -k uvicorn.workers.UvicornWorker -w 4 -b 0.0.0.0:8000 --timeout 120"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: llmbridge
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: llmbridge
    volumes: [ "pgdata:/var/lib/postgresql/data" ]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U llmbridge"], interval: 10s }
  redis:
    image: redis:7-alpine
    volumes: [ "redisdata:/data" ]
    healthcheck: { test: ["CMD", "redis-cli", "ping"], interval: 10s }
  nginx:
    image: nginx:1.27-alpine
    ports: [ "80:80" ]
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ../admin-web/dist:/usr/share/nginx/html:ro
    depends_on: [ api ]
volumes: { pgdata: {}, redisdata: {} }
```

### 3.3 nginx.conf（SSE 关键配置——**本项目最典型故障源**）

> **实际交付文件为 [`deploy/nginx.conf`](../../deploy/nginx.conf)，以它为准**（已含
> upstream keepalive、`client_max_body_size`、SPA fallback、assets 长缓存，
> 以及 `/admin/` 刻意不关 buffering 的取舍说明）。

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;
  index index.html;
  location / { try_files $uri $uri/ /index.html; }

  location /v1/ {
    proxy_pass http://api:8000;
    proxy_buffering off;          # SSE 必关：否则流式「卡住不出字」
    proxy_cache off;
    proxy_read_timeout 300s;      # 长回答防中断
    proxy_http_version 1.1;
    proxy_set_header Connection '';
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    add_header X-Accel-Buffering no;
  }
  location /admin/ {
    proxy_pass http://api:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }
}
```

### 3.4 前端构建

```bash
cd admin-web && npm ci && npm run build   # 产物 dist/
```

### 3.5 启动与初始化验证

```bash
docker compose --env-file ./.env -f deploy/docker-compose.yml up -d
curl -f http://localhost:8000/health                       # {"status":"ok"}
curl -X POST localhost:80/admin/auth/login -d '{"username":"admin","password":"admin123"}' -H 'Content-Type: application/json'
# 首次登录后【立即改密】（设计审核 R-08 强制项）
```

> ⚠️ **`--env-file ./.env` 不能省**：`-f` 指到 `deploy/` 后，compose 只在**编排文件所在目录**
> 找 `.env` 做变量插值，仓库根的 `.env` 读不到，缺了会报
> `required variable POSTGRES_PASSWORD is missing a value`。下文所有 `docker compose -f deploy/...`
> 命令同理。（`docker-compose.yml` 的 `env_file: ../.env` 只作用于容器内环境变量。）

### 3.6 容器库形态：一条命令，不需要源码

上面 3.1~3.5 是**源码形态**：镜像在目标机构建，前端 `dist` 通过 bind mount 进 nginx，
所以目标机必须持有源码目录。**容器库形态**把前端也做成镜像，于是目标机只需要一个地址、
一条命令：

```bash
# 发布侧（一次）：构建并推送 api + web + deploy 三个镜像
docker login --username=<账号> registry.cn-hangzhou.aliyuncs.com
bash deploy/publish-image.sh --tag 1.0.0

# 目标机（只要有 Docker 且能访问容器库）—— 就这一句
docker run --rm --entrypoint cat \
  registry.cn-hangzhou.aliyuncs.com/winyeahs/llmbridge-api:1.0.0 \
  /opt/llmbridge/deploy/docker-deploy.sh | bash -s -- --image
```

安装脚本放在 api 镜像里（`/opt/llmbridge/deploy/docker-deploy.sh`）：容器库是目标机
唯一一定能访问的地址（否则业务镜像也拉不下来），而安装流程随后要拉的就是这套镜像，
所以取脚本不会多下载一个字节。脚本里**内嵌了编排文件**，目标机除容器库外不访问任何外网。
`--entrypoint cat` 不能省 —— api 镜像默认入口会先做数据库初始化再起服务。

> **为什么不用 `curl raw.githubusercontent.com/... | bash`**：
> GitHub 在国内不可达，那条命令在目标机上是必然失败的。
>
> 另有 8 MB 的纯安装器镜像 `llmbridge-deploy`（只打印脚本），但它要求该仓库在容器库里
> 被设为**公开**；ACR 新建仓库默认私有，匿名拉取会 401。设为公开后可简化为
> `docker run --rm <registry>/llmbridge-deploy:1.0.0 | bash -s -- --image`。

| 对比项 | 源码形态（3.1~3.5） | 容器库形态（本节） |
|---|---|---|
| 编排文件 | `deploy/docker-compose.yml` | `deploy/docker-compose.image.yml` |
| nginx 服务名 | `nginx` | `web`（含内置 dist 与 nginx.conf） |
| 目标机需要源码 | 需要 | **不需要** |
| 目标机需要 GitHub | 需要（下载脚本） | **不需要** |
| 前端构建 | 必须本地 build dist | 镜像内已含 |
| 升级 | `git pull` + `up -d --build` | 改 `LLMBRIDGE_TAG` + `pull` + `up -d` |

两种形态共用 compose 项目名 `llmbridge` 与同一套数据卷，**换形态不丢数据**；
但服务名不同，切换前必须先 `down` 否则留下孤儿容器。

完整说明、完整问题排查与验证边界，见
[`05-安装打包说明.md`](05-安装打包说明.md) 的 §4.3 与 §6.1.1。

## 四、非 Docker 部署（备选）

> **更快的方式**：Linux 裸机（systemd）直接用一键脚本，它会顺带构建控制台前端并生成
> Nginx 站点配置 —— 这两步是手工最容易漏的（漏了就是「服务正常、浏览器白屏」）：
>
> ```bash
> curl -sSL https://raw.githubusercontent.com/dragonlin-ai/llmbridge/main/deploy/install.sh | sudo bash
> ```

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .
llmbridge-seed                    # 建表 + 默认管理员 + 评测样本 + 厂商接入目录（幂等；不跑也行，启动会自动做）
gunicorn app.main:app -k uvicorn.workers.UvicornWorker -w 4 -b 127.0.0.1:8000
# 或直接用内置入口（自动处理事件循环）：llmbridge-serve --workers 4
# systemd 单元：ExecStart=<venv>/bin/llmbridge-serve --workers 4，Restart=always
# 模板见 deploy/linux/llmbridge.service
```

## 五、环境变量清单

| 变量 | 必填 | 说明 |
|---|---|---|
| DATABASE_URL | 是 | 生产 `postgresql+psycopg://...`（**不是 asyncpg**：该驱动不在依赖内） |
| POSTGRES_PASSWORD | Compose 必填 | 同时用于初始化 db 与注入 api（`docker-compose.yml` 以 `:?` 强制） |
| AUTO_BOOTSTRAP | 否 | 默认 `true`：启动时自动建表 / 建默认管理员 / 预置厂商接入目录。生产若由 DBA 管库可置 `false`，改为显式跑 `llmbridge-seed` |
| REDIS_URL | 否 | 缺省=不启用缓存 |
| JWT_SECRET | **是** | 32B 随机 |
| ENCRYPTION_MASTER_KEY | **是** | 32B 随机；**丢失=全部厂商 Key 不可解**；离线备份 |
| ALLOW_LOCAL_BASE_URL | 否 | 生产**必须 false**（SSRF 白名单，独立于数据库类型判断） |
| JUDGE_PROVIDER | 是 | `mock`（生产默认）/ `jev`（出境决策通过后启用） |
| JEV_API_KEY / JEV_BASE_URL | 条件 | provider=jev 时必填 |
| ROUTE_CONFIDENCE_THRESHOLD_T2 | 否 | 默认 0.5 |
| DEFAULT_MODEL_ID | 否 | 默认 1 |
| REQUEST_TIMEOUT_MS / DECIDER_TIMEOUT_MS | 否 | 30000 / 3000 |
| ENABLE_TOOL_EXECUTION | 否 | 默认 `false`（纯透传，标准 OpenAI 语义） |

完整清单见 `05-安装打包说明.md` §八。

## 六、回滚方案

```bash
# 应用回滚
docker compose pull && docker compose up -d --no-deps api        # 上一镜像 tag
# 数据库回滚：用升级前的 pg_dump 备份还原（当前无 alembic 版本链可 downgrade）
zcat db-YYYY-MM-DD.sql.gz | docker compose exec -T db psql -U llmbridge -d llmbridge
# 验证：/health + 登录 + 试跑一条 L1 规则
```

## 七、常见问题

| 现象 | 排查 |
|---|---|
| 流式「卡住不出字」 | 99% 是 nginx `proxy_buffering` 未关；curl 直打 8000 对比 |
| 502 | `docker compose logs api`；db 未就绪时 alembic 失败最常见 |
| `database is locked`（开发） | SQLite 多 worker；生产换 PG |
| Redis 连不上 | 检查 REDIS_URL；确认服务仍应可用（降级设计），仅无缓存 |
| 密钥解密失败 | 主密钥与数据不匹配——**禁止**更换 master_key 后直接起服务 |
