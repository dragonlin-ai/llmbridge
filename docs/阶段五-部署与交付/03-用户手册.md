## 一、系统简介

面向两类用户：
- **第三方系统开发者**：把现有 OpenAI SDK 的 `base_url` 改指向本系统即可，`model` 传 `"auto"` 由系统自动选模型。
- **控制台管理员**：管理模型池、路由规则，在试跑台验证判定逻辑，用调用日志排查问题。

核心特点：接入零改造；判定分层（规则秒判 → Jev 语义判定 → 兜底保底）；全链路可观测（每次调用可回放「为什么选了这个模型」——以概率分布与打分形式呈现）。

## 二、系统要求

Chrome / Edge ≥ 100，Firefox ≥ 100；分辨率 ≥ 1366×768。

## 三、登录

1. 浏览器打开 `http://<host>/`，跳转登录页。
2. 输入管理员账号（首次部署为 admin/admin123，**登录后立即在「用户」处改密**）。
3. 连续 5 次失败锁定 10 分钟。

## 四、功能模块（对应控制台 10 页面）

### 4.1 路由试跑台（P0 · 最常用）

用途：**不消耗上游费用**地验证「一段文本会被路由到哪个模型」。

1. 左侧输入测试文本（可用示例快捷填充）。
2. 点击「试跑」。
3. 结果区自上而下：
   - **链路可视化条**：L1（绿）/ L2（紫·Jev）/ L3（红·兜底）三段，命中的高亮，其余灰显（悬停看跳过原因）；
   - **判定摘要**：命中层级、任务类别、选中模型、置信度、耗时、trace_id；
   - **Jev 概率分布图**：各类别概率降序条形，含 T2=0.5 阈值虚线——**整体低于阈值即说明会走兜底**；
   - **候选打分行**：各候选得分（悬停看命中规则）；
   - **原始 JSON**（折叠）。
4. 判定不符预期 → 去「路由规则配置」调整或去「模型池」改能力标签，回本页复测。

### 4.2 厂商接入点管理（P0 · 只填一个 Key 就能用）

系统已**内置 13 家国内主流厂商的全部接入方式**（DeepSeek、阿里云百炼、智谱 GLM、月之暗面 Kimi、火山方舟、
百度千帆、腾讯混元、MiniMax、零一万物、阶跃星辰、百川智能、硅基流动、小米 MiMo），以及它们的代表模型。
你**不需要**查 base_url、不需要建模型、不需要查价格、不需要打能力标签——**只需填入 API Key**。

**一家厂商可能有多条接入方式，它们是互不相通的凭证。**
同一家厂商的「按量 API」与「订阅套餐」密钥、端点、计费都不一样，拿 A 的 Key 填到 B 上会 401。
所以页面按**厂商分组**：一家厂商一张卡片，卡内把它所有接入方式分行列出，各填各的 Key。

| 卡片内你会看到 | 含义 |
|---|---|
| `按量 API` | 开放平台的通用商业接口，按 token 后付费。**合规风险最低，优先用它** |
| `资源包` / `批处理` | 与「按量 API」**同 Key 同端点**，只是结算方式不同，故不单独成行 |
| `编程订阅套餐` | 订阅制（专属 Key + 专属端点），包月积分 / 次数。**V1.6 起已纳入路由**，见下 |
| `Token 订阅套餐` | 订阅制（专属 Key + 专属端点），包月 Token 额度。**V1.6 起已纳入路由**，见下 |
| `OpenAI 兼容` / `Anthropic 兼容` | 上游协议。目前只有 OpenAI 兼容的被支持 |
| `待配置密钥`（黄）/ `已接入`（绿）/ `已停用`（灰） | 凭证状态 |
| `单价为参照值`（蓝） | 订阅制通道没有真实 token 单价，页面显示的是**成本参照值**，仅供排序参考 |

**接入三步**：

1. 打开「厂商接入」。卡片已按厂商分好组，顶部可用「全部 / 待配置 / 已接入 / **订阅类**」快速筛选。
2. 找到目标通道 → 点行内「**填写密钥**」→ 粘贴该通道控制台的 API Key → 保存。
   - 每行备注里直接给了该通道**专属的**密钥申请入口，点「去申请 →」即可。
   - 保存后只显示掩码 `sk-****abcd`，明文不回显、不落库（AES-256-GCM 加密存储）。
3. 保存成功即完成接入：系统会**自动启用**该通道及其全部内置模型，并弹提示告知本次自动启用了什么。
   回到「模型池管理」即可看到其模型状态变为「参与路由」。

> **⚠️ 关于「订阅类套餐」（编程订阅 / Token 订阅）——请务必读一遍**：
> 这类通道**已纳入路由**（V1.6 起），填 Key 后会被自动启用、会进入候选池。
> 但厂商条款**普遍限定**它们只能在厂商官方支持的编程 / 智能体工具中**交互式**使用，
> **不得作为应用后端、自动化脚本或批量任务的主调用通道**；违规可能导致套餐停用或 Key 封禁。
> 本系统对外提供 `/v1` 接口，从上游看正属于「应用后端」——**这条合规风险由使用者自行承担**。
>
> 系统不会隐瞒这件事，而是**如实告知**：
> - 通道行上有「⚠ 条款警示」按钮，点开是**厂商官方条款原文**；
> - 给订阅通道**首次填 Key 时**会弹窗二次确认（不是一闪而过的提示）；
> - 该通道所有模型标 **`单价为参照值`**——订阅制没有真实 token 单价，
>   这个数字是按「套餐价 ÷ 额度」折算、或取按量标准价替代的，**只能用于排序参考，不能用于成本核算**。
>
> **给你的选择**：如果你的场景是「产品后端统一调用」，建议**优先用「按量 API」通道**；
> 订阅类通道适合自有工具、内部试用等场景。两者可以在同一张卡片里并存，各填各的 Key，系统按成本与优先级择优。
>
> **若某条订阅通道里没有模型**：说明厂商没有公布可折算的单价，系统**刻意没有收录**——
> 因为凭空填一个 0 会让它在成本排序里被异常偏爱、长期霸占路由。
> 你可以自行在「模型池管理」里按真实情况添加。**留空也不要填 0。**
>
> **口径说明**：是否「已接入」取决于**密钥能否解密**，内置但未填 Key 的通道写的是非法占位密文，
> 因此**绝不会被选中去发起注定失败的调用**——这保证了「兜底率 100%」不被未接入通道破坏。
>
> **价格说明**：内置的是**参考价**（元/百万 token），非实时报价，存在时间漂移 / 平台差异 / 计费口径差异三类失真；
> 订阅类通道另加一类——**套餐等效单价依赖厂商公布的额度口径**。
> 涉及实际成本核算前，请以厂商官网价目表核对，必要时在「模型池管理」里改单价。缺失价格留空而非填 0。

**其他操作**：

- **新增厂商**（内置目录之外的自建/私有化接入点）：名称 + base_url（仅 https，禁止内网地址）+ API Key。
- **连通性测试**：单条「测试」按钮返回延迟；批量测试入口在列表工具栏。
- **新增模型**（内置目录之外的模型）：选厂商、填 model_name（厂商真实名）、勾能力标签（决定 L2/L3 选中概率）、
  单价（元/百万 token，成本核算依据）、上下文窗口、**优先级**（数值越小越优先，**即降级顺序**）。
  > ⚠️ 能力标签只能取既有 6 类：`general` / `code_generation` / `translation` / `summarize` /
  > `complex_reasoning` / `long_context`。写别的值不会被识别，该模型在兜底时只能靠价格参与排序。
- 启停开关：停用厂商或模型即不参与路由，已进行中的调用不受影响。

### 4.3 模型池管理（P0）

- 列表含一列 **「路由状态」**（三态）：`参与路由` / `厂商未接入` / `已停用`。
  - `厂商未接入` = 该模型所属厂商还没填 Key——**去厂商页填 Key 即可，不必在此建模型**。
  - 勾选 **「仅看参与路由」** 可过滤出真正会被选中的模型，默认按该状态排序。
- 逐个模型可改：能力标签、单价、上下文窗口、优先级、启停。
- 修改能力标签是**提升路由准确率最有效的手段**：任务类型与标签不匹配时，L2 判定正确也会在 L3 选错模型。

### 4.4 路由规则配置（P0）

- 「新增规则」→ 条件编辑器：字段（文本/token 长度）+ 操作符（包含/正则/大于…）+ 值；「JSON 模式」切换可直接贴 JSON（保存时校验，正则非法会拒绝）。
- **拖拽调整优先级**：列表直接拖动，松手自动保存（同命中取靠前者）。
- 相同条件 + 相同优先级会被拦截提示冲突。

### 4.5 调用日志（P0）

- 列表：时间、trace_id、层级、最终模型、路由耗时、总耗时、token、成本、状态、兜底原因。
- 筛选组合：时间段 + 模型 + 层级 + 状态 + 「仅看降级」。
- 点 trace_id 进 **Trace 详情**：时间轴（各阶段耗时）+ 判定快照（概率分布、候选打分）+ `fallback_reason`——**排查「为什么没走预期模型」的唯一权威入口**。

### 4.6 登录页 / 概览看板 / 决策样本 / 评测看板 / 用量成本

- 概览（P1）：今日请求量、成功率、P95 路由延迟、兜底率、成本、层级/任务分布、模型 TOP N。
- 决策样本（P1）：维护判定语料；支持从调用日志一键沉淀。
- 评测看板（P1 骨架）：展示「计划中」，评测跑批用 `scripts/run_eval.py`。
- 用量与成本（P2）：按模型/时间聚合，前端导出 CSV。

## 五、第三方接入指引（给下游开发者）

```python
from openai import OpenAI
client = OpenAI(base_url="http://<host>/v1", api_key="<你拿到的 Key>")
resp = client.chat.completions.create(
    model="auto",                      # 关键：触发自动路由
    messages=[{"role": "user", "content": "你好"}],
)
# 想知道背后用了谁：
print(resp._response.headers.get("x-router-model"))        # 实际模型
print(resp._response.headers.get("x-router-trace-id"))     # 报障凭据
```

- 流式同原生用法（`stream=True`）。
- **失败语义**：你只会收到 200（成功）、4xx（你的参数/鉴权问题）、以及极少数 5xx（平台故障）。厂商侧的限流/抖动由平台内部降级消化，你无感。

## 六、常见问题

| 问题 | 处理 |
|---|---|
| 忘记密码 | 运维在服务器执行 `python -m app.seed --reset-admin` 重置（见运维手册） |
| 试跑显示「判定失败」 | 链路条红色段悬停看原因；判定器不可用时会走兜底，功能不受阻 |
| 某请求没走预期模型 | 日志按 trace_id 查 `fallback_reason`：LOW_CONFIDENCE→看概率分布图；UPSTREAM_UNAVAILABLE→查模型池连通性 |
| 内置模型显示「厂商未接入」 | 该厂商还没填 Key。去「厂商接入点管理」点行内「填写密钥」即可，保存后系统自动启用该厂商与模型 |
| 填了 Key 但模型仍不参与路由 | 三种可能：① Key 本身无效（保存时有校验，失败会提示）；② 厂商或模型被手动停用了；③ 模型自身 `enabled=False`。在模型页勾「仅看参与路由」可快速定位 |
| 试跑台的候选打分里没有某模型 | 属正常——候选池只含「参与路由」的模型（厂商已接入 + 已启用 + 模型已启用），未接入厂商的模型不会进池 |
| 单价为什么是可改的参考价 | 内置价是元/百万 token **参考价**，非实时报价；请以厂商官网核对后按需修正。不要把未知价格填 0 |
| 订阅套餐通道能填 Key 吗？填了会怎样？ | 能。填 Key 后**会自动启用并纳入路由**（V1.6 起）。但厂商条款通常禁止把订阅套餐当应用后端用，**合规风险自担**——系统已在通道行给出官方条款原文与弹窗确认，请先读完再决定 |
| 为什么某条订阅通道里一个模型都没有？ | 厂商未公布可折算的单价，系统**刻意不收录**（填 0 会让它霸占成本排序）。需要就在「模型池管理」手工添加，**留空也不要填 0** |
| 同一家厂商为什么有好几张通道卡？ | 一家厂商的多条接入方式是**互不相通的凭证**（密钥/端点/计费都不同）。按厂商分组展示，卡内分行，各填各的 Key |
| 「单价为参照值」是什么意思？ | 该通道是订阅制，没有真实 token 单价。这个数字是按套餐价折算或取按量标准价替代的，**只可用于排序参考，不可用于成本核算** |
| 流式卡住不出字 | 先 curl 直打后端 8000 排除业务，再查 Nginx `proxy_buffering off` 是否配置 |
| 修改规则后判定没变 | 路由缓存 1 小时；在试跑台复测（试跑走同链路同缓存）；急生效可重启 api 或等失效 |

## 七、术语表

| 术语 | 含义 |
|---|---|
| L1/L2/L3 | 路由三层：规则短路 / Jev 判定 / 组合兜底 |
| Jev | TypeSafe AI 决策模型，输出带校准概率的类型化判定，不生成文本 |
| 兜底 | 判定异常或低置信时改用默认候选，保证总有结果 |
| 降级 | 目标模型不可用时按优先级换备选 |
| fallback_reason | 兜底/降级原因码（LOW_CONFIDENCE 等） |
| trace_id | 单次请求全链路标识，报障必带 |
| T2 | 置信度阈值（默认 0.5），低于即兜底 |
| Mock 判定器 | 内置无外部依赖的判定实现，离线/私有化用 |
| 接入通道 | `provider` 表的一行。**一条通道 = 一套独立的 Key / 端点 / 计费**，不是一家厂商 |
| access_kind | 接入形态，五种：按量 API / 资源包 / 批处理 / 编程订阅套餐 / Token 订阅套餐 |
| 订阅类通道 | `coding_plan` + `token_plan` 的合称。无真实 token 单价，单价是参照值 |
| terms_note | 厂商官方条款警示原文，落 `provider.terms_note`，在通道行可展开 |
| 可路由 | 该模型真能进候选池（厂商已接入 + 通道形态支持 + 协议有适配器 + 双方已启用） |
| excluded_channel | 试跑台候选池四分类之一：因通道形态或协议被排除的模型数（V1.6 后正常为 0） |
