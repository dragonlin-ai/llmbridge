## 一、公共约定

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 对外 Base URL | `http(s)://<host>:`/v1 |
| 控制台 Base URL | `http(s)://<host>:`/admin |
| 开发端口 | 后端 8000；前端开发 5173（Vite 代理 /v1 与 /admin 到 8000） |
| 请求格式 | `application/json`（UTF-8） |
| 鉴权 | 对外：`Authorization: Bearer <api_key>`；控制台：`Authorization: Bearer <jwt>` |

### 1.2 公共响应格式（控制台接口）

```json
{
  "code": 0,
  "message": "ok",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | 0 = 成功；非 0 见错误码表 |
| message | string | 人类可读信息 |
| data | object \| array \| null | 业务数据 |

> **对外接口 `/v1/chat/completions` 不使用此信封**，严格返回 OpenAI 兼容格式——第三方系统零改造是硬约束。

### 1.3 错误码表

| code | HTTP | 含义 | 触发场景 |
|---|---|---|---|
| 0 | 200 | 成功 | - |
| 1001 | 401 | 未认证 | 缺少 / 非法 JWT 或 API Key |
| 1002 | 403 | 无权限 | readonly 角色执行写操作 |
| 1003 | 422 | 参数校验失败 | Pydantic 校验未通过 |
| 1004 | 404 | 资源不存在 | path 中的 id 无效 |
| 1005 | 409 | 资源冲突 | 规则优先级冲突 / 用户名重复 |
| 2001 | 429 | 限流触发 | IP / 租户 / 模型级限流 |
| 2002 | 402 | 配额超限 | 日配额用尽 |
| 3001 | 500 | 路由判定失败 | 三层全部未产出可用模型（**理论上不应出现**，兜底率 100% 兜住） |
| 3002 | 502 | 所有候选模型不可用 | 上游全部超时 / 429 / 5xx |
| 3003 | 504 | 上游超时 | 超过 REQUEST_TIMEOUT_MS |
| 3004 | 503 | 判定器不可用 | Jev 与本地判定器同时不可用（此时 L3 兜底默认模型，不对外报错） |

> **对外口径再强调**：3001~3004 仅出现在极端故障且未被兜底链吸收时；常规路径下第三方永远拿到 200 或 4xx（其自身输入问题）。

### 1.4 分页与排序（控制台列表接口通用）

查询参数：`page`（默认 1）、`page_size`（默认 20，最大 100）、`order_by`、`order`（`asc`/`desc`）。
响应 `data`：

```json
{ "total": 233, "page": 1, "page_size": 20, "items": [ ] }
```

## 二、对外接口（/v1）

### 2.1 POST /v1/chat/completions —— 统一对话入口（OpenAI 兼容）

**鉴权**：`Authorization: Bearer <api_key>`（MVP 阶段 api_key 即控制台签发的接入凭据，写入 provider 备注；V2 演进为独立 api_key 表）。

**请求体**：

```json
{
  "model": "auto",
  "messages": [
    { "role": "user", "content": "帮我写一个 Python 快排" }
  ],
  "stream": false,
  "temperature": 0.7,
  "max_tokens": 2048
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| model | string | 是 | `"auto"` 触发自动路由；也可显式传模型池中的 `model_name`（跳过判定，直接调用） |
| messages | array | 是 | OpenAI 格式，role ∈ system/user/assistant |
| stream | bool | 否 | 默认 false；true 时走 SSE |
| temperature / max_tokens / top_p | - | 否 | 透传给下游 |

**非流式响应**（OpenAI 兼容体 + 本系统响应头）：

```json
{
  "id": "chatcmpl-7f3a...",
  "object": "chat.completion",
  "created": 1758441600,
  "model": "deepseek-coder",
  "choices": [
    { "index": 0,
      "message": { "role": "assistant", "content": "以下是快速排序实现……" },
      "finish_reason": "stop" }
  ],
  "usage": { "prompt_tokens": 18, "completion_tokens": 342, "total_tokens": 360 }
}
```

**响应头（基线 3.1.1 固定 5 字段）**：

| 响应头 | 示例 | 取值时机 |
|---|---|---|
| x-router-model | `deepseek-coder` | 始终 |
| x-router-layer | `L1` / `L2` / `L3` | 始终 |
| x-router-task-type | `code_generation` | 仅 L2 命中 |
| x-router-confidence | `0.92`（L1 恒 `1.0`） | 始终 |
| x-router-trace-id | `7f3a…` | 始终 |

**流式响应**：`Content-Type: text/event-stream`，分片格式与 OpenAI 一致，终止 `data: [DONE]`。**首个分片下发前路由决策必须已完成**（基线：不允许先返回再改道）。元信息仍走响应头（SSE 下 body 无法附加字段）。

**错误**：非法 body → 1003；鉴权失败 → 1001；全部候选不可用 → 3002（此为兜底链吸收后的最终失败）。

### 2.2 契约测试要点（供阶段四直接引用）

1. `model="auto"` 与 `model="deepseek-coder"`（显式指定）各自返回 200。
2. 响应头 5 字段存在且取值合法；L1 命中时 `x-router-task-type` 不存在。
3. `stream=true` 时分片可解析、以 `[DONE]` 结束、响应头同样携带。
4. 请求进入前先触发限流（1001/2001 优先级高于业务处理）。

## 三、控制台接口（/admin）

### 3.1 POST /admin/auth/login —— 登录

请求：

```json
{ "username": "admin", "password": "admin123" }
```

响应 `data`：

```json
{ "access_token": "eyJhbGciOi…", "token_type": "bearer", "expires_in": 86400, "role": "admin" }
```

错误：用户名或密码错误 → 1001；连续 5 次失败锁定 10 分钟 → 1001（message 区分）。

### 3.2 厂商接入点 /admin/providers

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /admin/providers | 列表（分页） |
| POST | /admin/providers | 新增 |
| PUT | /admin/providers/{id} | 更新（api_key 不传则不修改） |
| DELETE | /admin/providers/{id} | 删除（存在关联模型时 → 1005） |
| POST | /admin/providers/{id}/test | 连通性测试 |

**POST /admin/providers 请求**：

```json
{ "name": "DeepSeek", "base_url": "https://api.deepseek.com/v1", "api_key": "sk-xxxx" }
```

**响应 data（回显脱敏）**：

```json
{ "id": 1, "name": "DeepSeek", "base_url": "https://api.deepseek.com/v1", "api_key_masked": "sk-****abcd", "enabled": true }
```

**base_url 安全校验**：仅允许 `https` scheme（开发环境允许 http://localhost）；经 SSRF 白名单校验，命中内网地址段（10/8、172.16/12、192.168/16、127/8、169.254/16、元数据地址 169.254.169.254）→ 1003 拒绝。

**POST /admin/providers/{id}/test 响应**：

```json
{ "ok": true, "latency_ms": 187, "detail": "models 列表可达" }
```

### 3.3 模型池 /admin/models

CRUD 同上模式。核心字段：`provider_id`、`model_name`、`display_name`、`capabilities`（字符串数组）、`input_price`、`output_price`、`context_window`、`enabled`、`priority`（越小越优先）。

**POST /admin/models 请求**：

```json
{
  "provider_id": 1,
  "model_name": "deepseek-coder",
  "display_name": "DeepSeek Coder",
  "capabilities": ["code_generation"],
  "input_price": 2.0,
  "output_price": 8.0,
  "context_window": 65536,
  "priority": 10,
  "enabled": true
}
```

**业务校验**：`(provider_id, model_name)` 唯一 → 冲突 1005；priority 相同不视为冲突（降级顺序按 id 补序）。

**删除的引用语义（V1.1 补充，缺陷 D-12 / D-16 整改）**：`model.id` 被 4 张表外键引用，按语义分类处理，禁止一刀切。

| 引用方 | 列约束 | 默认删除 | `force=true` |
|---|---|---|---|
| `route_rule.target_model_id` | **NOT NULL** | 409（1005），提示去「路由规则配置」改绑或删除 | **仍 409** —— 解绑不了，这是唯一硬阻止项 |
| `eval_case.expected_model_id` | NULL 允许 | 409（1005），提示可使用强制删除 | 清空期望模型、**用例保留**，计入 `unbound_evals` |
| `request_log.final_model_id` | NULL 允许 | 解绑 NULL，日志保留，计入 `unbound_logs` | 同左 |
| `decision_sample.chosen_model_id` / `actual_model_id` | NULL 允许 | 解绑 NULL，样本保留，计入 `unbound_samples` | 同左 |

**GET /admin/models/{id}/references** —— 删除前预检，供前端生成确认文案（避免「先失败再重试」）：

```json
{ "route_rules": 0, "eval_cases": 2, "request_logs": 14, "decision_samples": 0, "forceable": true }
```

`forceable = (route_rules == 0)`。

**DELETE /admin/models/{id}?force=true** —— 强制删除，返回解绑计数：

```json
{ "unbound_logs": 14, "unbound_samples": 0, "unbound_evals": 2 }
```

> 设计约束：凡是返回「请先解除 X 引用」的报错，X 必须存在可操作的解除入口；若 X 没有管理界面（如当前的 `eval_case`），则必须提供**明确告知后果 + 二次确认**的受控强制路径（见 U-10）。

### 3.4 路由规则 /admin/rules

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /admin/rules | 列表，按 priority 升序 |
| POST | /admin/rules | 新增 |
| PUT | /admin/rules/{id} | 更新 |
| PUT | /admin/rules/priorities | 批量调优先级（拖拽排序提交） |
| DELETE | /admin/rules/{id} | 删除 |

**POST /admin/rules 请求**：

```json
{
  "name": "长文走大上下文",
  "priority": 15,
  "type": "token_len",
  "condition_json": { "all": [ { "field": "token_len", "op": "gt", "value": 8000 } ] },
  "target_model_id": 4,
  "enabled": true,
  "remark": "超过 8k token 的输入路由 gpt-4o"
}
```

**condition_json Schema（条件编辑器的存储与校验契约）**：

```json
{
  "all": [
    { "field": "text | token_len", "op": "op", "value": "..." }
  ]
}
```

| field | 可用 op | value 类型 | 说明 |
|---|---|---|---|
| text | contains / regex / not_contains | string | 对拼接后的用户输入做匹配 |
| token_len | gt / gte / lt / lte | int | 估算 token 数（≈ 字符数/2.5，中英混合粗估即可） |

校验规则：`all` 数组非空；op 必须在对应 field 的枚举内；regex 编译失败 → 1003；**同 priority 且条件完全相同的两条规则 → 1005 冲突**（设计审核报告 TR 复核项）。

**PUT /admin/rules/priorities 请求**：

```json
{ "ordered_ids": [2, 1, 3] }
```

按数组顺序重排 priority 为 10, 20, 30…（间隔 10，便于后续插入）。

### 3.5 决策样本 /admin/samples

CRUD + 批量导入。字段：`input_text`、`task_type`、`probabilities_json`、`chosen_model_id`、`source`（manual / log_mined）。
`POST /admin/samples/import`：接受数组批量导入，逐条校验，失败的行在响应中列明行号与原因，合法行照常入库。

### 3.6 调用日志 /admin/logs

**GET /admin/logs** 查询参数：

| 参数 | 说明 |
|---|---|
| trace_id | 精确匹配 |
| model_id / router_layer / status | 筛选 |
| has_fallback | `true` 只看发生兜底/降级的记录 |
| start_time / end_time | ISO 8601，闭区间 |
| page / page_size / order_by（默认 created_at desc） | 分页 |

**响应 items 单条**：

```json
{
  "id": 1001,
  "trace_id": "7f3a…",
  "router_layer": "L2",
  "final_model_id": 3,
  "final_model_name": "gpt-4o-mini",
  "final_model_key": "gpt-4o-mini",
  "route_latency_ms": 312,
  "latency_ms": 2240,
  "prompt_tokens": 18,
  "completion_tokens": 342,
  "cost": 0.0174,
  "status": "success",
  "fallback_reason": null,
  "created_at": "2026-09-21T13:00:00Z"
}
```

**模型字段口径（D-19 整改）**：`final_model_name` 是运营别名，`final_model_key` 是**真实调用的模型标识**（落库当时的 `model_name`）。两者取值优先级为 **落库快照 > 外键 join**——删除模型时 `final_model_id` 会被按设计解绑为 `NULL`，此时只有快照能还原「这条请求当时真实调用了哪个模型」。两个字段同时为 `null` 只有一种情况：该条日志产生于快照列上线之前，且其模型已被删除（历史既成损失，无法回溯）。

**GET /admin/logs/{trace_id}** —— Trace 详情：上表全部字段 + `router_output_json` 完整判定快照（task_type / probabilities / confidence / 候选打分数组 / 特征标记）。**不含请求与响应原文**（安全方案：输入文本脱敏后才落库，响应原文不落库，仅存 token 与成本）。

### 3.8 POST /admin/route/preview —— 路由试跑（核心调试接口）

**语义**：执行「鉴权外的完整路由链路」——L1 → L2（Jev 判定）→ L3 映射与兜底。两种模式：

| 模式 | 触发 | 行为 | 成本 |
|---|---|---|---|
| **仅决策**（默认） | `execute=false` | 只跑决策，返回选中模型 | 零 token 消耗 |
| **决策 + 调用** | `execute=true` | 决策后再**真实调用**选中模型，返回其输出 | 产生真实 token 与费用 |

**两条硬约束**（实现与文档同步留痕）：

1. **两种模式都不写 `request_log`**。试跑属诊断流量，落库会污染线上成功率与成本口径。副作用是试跑产生的调用**不会**出现在「调用日志」「用量与成本」页面。
2. **执行模式不做降级**。降级是线上保护；试跑台的职责是如实暴露「选中的模型到底通不通」。自动降级会让「选中模型不可用」被另一个候选的成功掩盖。失败时原样返回错误分类，不重试。

**请求**：

```json
{ "text": "帮我写一个 Python 快排，并处理边界条件", "session_id": "debug-session-1",
  "execute": true, "max_tokens": 512 }
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| text | string | 是 | 测试文本，超长截断规则与线上一致 |
| session_id | string | 否 | 模拟会话，供 session_pin 类规则测试 |
| execute | bool | 否 | 默认 `false`。为 `true` 时真实调用选中模型并回带输出 |
| max_tokens | int | 否 | 默认 `512`，范围 `1~4096`。仅执行模式生效，用于限制误操作产生的费用 |

**响应**：

```json
{
  "hit_layer": "L2",
  "task_type": "code_generation",
  "selected_model": {
    "model_id": 2,
    "model_name": "deepseek-coder",
    "display_name": "DeepSeek Coder"
  },
  "confidence": 0.94,
  "probabilities": { "code_generation": 0.94, "general": 0.03, "translation": 0.02, "summarize": 0.01 },
  "features": { "complexity": 0.42, "has_code": 0.87, "is_sensitive": 0.02 },
  "candidates": [
    { "model_id": 3, "model_name": "glm-5.3", "display_name": "glm-5.3", "score": 0.7,
      "input_price": 0.0, "eligibility": "none", "in_pool": true, "picked": true, "matched_rule": null },
    { "model_id": 2, "model_name": "deepseek-v4-flash", "display_name": "deepseek-v4-flash", "score": 0.575,
      "input_price": 2.0, "eligibility": "none", "in_pool": true, "picked": false, "matched_rule": null }
  ],
  "selection_basis": "模型池中没有任何模型声明「translation」能力标签，退化为按成本排序（单价越低得分越高，同价按 priority 取先）",
  "hit_rule": null,
  "latency_ms": 356,
  "trace_id": "preview-3b8c…",
  "judge_provider": "jev",
  "active_decider": "jev",
  "decider": "jev",
  "decider_error": null,
  "execution": {
    "attempted": true,
    "ok": true,
    "model_id": 1,
    "model_name": "qwen3.8-flash",
    "display_name": "qwen3.8-flash",
    "provider_id": 3,
    "provider_name": "阿里云百炼",
    "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "latency_ms": 2475,
    "content": "数据库索引就像书的目录……",
    "finish_reason": "stop",
    "usage": { "prompt_tokens": 68, "completion_tokens": 57, "total_tokens": 125, "reasoning_tokens": 29 },
    "cost": 0.0,
    "model_echo": "qwen3.8-flash",
    "error_code": null,
    "error": null
  }
}
```

| 字段 | 说明 |
|---|---|
| hit_layer | L1：`task_type/probabilities/features` 为 null，`hit_rule` 为命中的规则对象；**L1 短路不经判定器**，故 `decider` 为 null 属正常；L2：全部字段有效；L3：低置信或判定器异常后的映射结果，`fallback_reason` 说明原因 |
| candidates | **排序即真实挑选顺序，首行恒为 `selected_model`**（D-18 整改后与 `pipeline.score_candidates` 同源）。字段：`score`（能力 0.6 + 成本 0.25 + 延迟 0.15）、`input_price`、`eligibility`（`hit` 命中能力标签 / `none` 未声明 / `null` 表示 L1 规则直指不走打分）、`in_pool`（是否参与本次挑选）、`picked`（是否为本轮选中）。L1 命中时仅一项且 `matched_rule` 指向规则 |
| selection_basis | 一句话解释「为什么是它」。无模型声明对应能力标签时会明说「退化为按成本排序」——这是最常见的退化场景，不写清楚就无法解释「为什么选了它」 |
| latency_ms | 本次试跑的**路由链路**总耗时（对照 ≤800ms P95 口径）；执行模式的上游耗时另见 `execution.latency_ms` |
| judge_provider / active_decider / decider | 分别为「配置的判定器」「本次装载的实现」「实际产出判定的实现」。三者不一致（如配 `jev` 却因缺 key 退回 `mock`）即表示判定未真正生效——**不能只看配置值** |
| execution | `null` 表示本次仅决策。`ok=false` 时看 `error_code`：`PROVIDER_UNAVAILABLE`（厂商不存在/禁用）、`KEY_DECRYPT_FAILED`（密钥解密失败）、`UPSTREAM_UNAVAILABLE`（上游报错/不可达）、`UPSTREAM_ERROR`（其他异常） |

> `features.complexity` 为 **0~1 浮点**（由 Jev 的 `score`(0~2 期望值) 归一化而来），非类别字符串。
> `usage.reasoning_tokens` 是推理模型的思考 token，**已包含在** `completion_tokens` 内——故 `max_tokens` 为 8 时 `completion_tokens` 仍可能大于 8。

**错误**：text 为空 → 1003；判定器不可用且默认模型也未配置 → 3004（此为试跑台唯一可见 3004 的场景）。**执行模式的上游失败不返回 4xx/5xx**，而是 HTTP 200 + `execution.ok=false` + `error_code`，以免「诊断工具自身报错」掩盖决策信息。
