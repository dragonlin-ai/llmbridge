## 二、密钥管理

### 2.1 存储
- 厂商 API Key 经 **AES-256-GCM** 加密后落库（`api_key_encrypted`）；nonce 每次加密随机生成，密文格式 `v1:<nonce_b64>:<ciphertext_b64>`（带版本前缀便于轮换迁移）。
- 主密钥 `ENCRYPTION_MASTER_KEY` 仅从环境变量注入；**严禁入 git**（.gitignore 已强制忽略 .env）。

### 2.2 使用与回显
- 解密只发生在两个位置：adapters 发起上游请求时、连通性测试时。其余任何代码路径（含日志、异常栈、试跑台）只允许出现掩码 `sk-****abcd`。
- 控制台回显**永远掩码**；更新时 api_key 不传 = 不修改。

### 2.3 主密钥生命周期
- 生成：`python -c "import secrets;print(secrets.token_urlsafe(32))"`。
- 备份：离线介质（密码管理器/加密 U 盘），**主密钥丢失 = 所有厂商 Key 无法解密**（运维手册高危项）。
- 轮换（V1.1）：新密钥加密旧数据逐行 re-encrypt，`v1:` 前缀保证灰度期双密钥可解。

## 三、判定出境合规（Jev 特有）

- Jev 官方 API 为境外服务：调用判定时**用户输入文本将出境**。
- MVP 处置：
  1. 判定输入**最小化**——只发送经截断的输入文本（≤1000 字符），不携带 messages 历史与 system prompt；
  2. `judge_provider=mock` 配置位保留，境内/私有化部署一键切换（BaseDecider 双实现）；
  3. 控制台登录后首屏展示数据出境提示条；
  4. **遗留决策项（HD）**：是否接受生产环境出境调用。未决前生产默认 `mock`。

## 四、控制台安全

- 口令 bcrypt（cost≥12）；登录连续失败 5 次锁定 10 分钟（内存计数即可，Redis 可选）。
- JWT：HS256，`exp=86400s`，payload 仅 `{sub, role}`；**不设 refresh token**（MVP 过夜重登可接受）。
- 角色权限：`admin` 全部读写；`readonly` 全部 GET（deps 层按 method 拦截，返回 1002）。
- 登出仅前端清 token（无服务端黑名单，MVP 接受；V2 配 Redis 黑名单）。

## 五、对外 API 安全

- 鉴权：`Authorization: Bearer <api_key>`；api_key 首次由 provider 配置派生（sha256 前 16 位 + 随机后段，哈希比对）。
- 限流（Redis 滑窗，Redis 不可用则放行并 WARN）：默认 60 次/分钟/API Key，配置可调。
- 配额：provider 日配额，超限 2002。
- **错误信息最小化**：对外错误只回 `{error:{message,type}}`，不暴露内部模块名/堆栈/SQL；5xx 统一替换为业务码 3002/3003 文案。

## 六、日志安全

- request_log.input_text 截断 2000 字符；`router_output_json` 不含原文。
- 敏感词脱敏（正则替换手机号/邮箱/身份证为 `***`）在写入前完成，开关可配。
- 日志文件权限 600；容器内以非 root 运行。

## 七、SSRF 防护（provider.base_url）

新增/更新 provider 时校验：
1. scheme 仅 `https`（开发环境放行 `http://localhost*`）；
2. 解析域名后拒绝私网段：`10/8, 172.16/12, 192.168/16, 127/8, 169.254/16, ::1, fc00::/7`；
3. 拒绝 IP 直连形式的主机名（防止 `http://192.168.1.1/` 绕过域名直觉）；
4. 连通性测试的出网请求同样走该校验 + 禁止跟随重定向跨 scheme。

## 八、依赖与供应链

- Python：`pip-audit` 进 CI；依赖锁定 `requirements.lock`。
- 前端：`npm audit --audit-level=high`；lockfile 提交。
- Docker：官方 python:3.11-slim 基础镜像，固定 digest。

## 九、审计与验收对照

| 审计项 | 落点 |
|---|---|
| 控制台写操作（增/删/改规则、密钥） | 记录操作者/时间/资源 id（MVP 写入应用日志，V1.1 独立 audit 表） |

| 验收项（对应 04-验收标准） | 验证方法 |
|---|---|
| API Key 不出现在任何日志 | grep 日志文件中的明文 Key 片段 |
| 密文存储 | 直接查库确认 api_key_encrypted 非 `sk-` 前缀明文 |
| SSRF 拦截 | 尝试保存 `http://127.0.0.1:8000` → 1003 |
| 越权 | readonly token 调 POST /admin/rules → 1002 |
