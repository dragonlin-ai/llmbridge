## 三、分层职责与依赖方向

```
api ──▶ router_engine ──▶ deciders
 │            │
 │            └──▶ adapters ──▶ 外部 HTTP
 └────▶ db / services
（依赖只允许向左下；router_engine 不得 import api，deciders 不得 import db）
```

- `api` 层做参数校验与组装，**不含业务逻辑**。
- `router_engine/pipeline.py` 是唯一编排点；各层模块只输出 `Decision | None`。
- `adapters` 内禁止 import `db`——模型数据由 pipeline 以 `ModelOut` 传入。

## 四、数据库与会话

- `session.py`：`create_engine` + `sessionmaker`；SQLite 下 connect 事件里执行 `PRAGMA journal_mode=WAL; PRAGMA synchronous=NORMAL;`
- 开发 `DATABASE_URL=sqlite:///./llmbridge.db`；生产 `postgresql+asyncpg://...`
- request_log 写入走**后台批量**：内存队列 + `asyncio.create_task` 每 1s 或 50 条 flush（进程退出时 atexit 冲洗）。表定义见《05-数据库设计.sql》，字段一一对应。

## 五、Redis 缓存设计

| Key | 值 | TTL | 用途 |
|---|---|---|---|
| `route:cache:{sha256(normalized_text)}` | Decision JSON | 3600s | 路由幂等缓存（normalized=去首尾空白+统一空白符） |
| `ratelimit:{api_key}` | 计数 | 60s 滑窗 | 对外限流 |
| `quota:{provider}:day` | 计数 | 至当日 24h | 日配额 |

**降级原则（TR-012）**：所有 Redis 操作包在 try/except 里，`REDIS_AVAILABLE=False` 时路由缓存直查、限流放行并 WARN——Redis 故障绝不阻断主链路。

## 六、异步与并发

1. 全链路 async；**禁止在协程内调用阻塞 IO**（requests、time.sleep、同步 SQLAlchemy）。
2. httpx.AsyncClient 在 lifespan 创建单例：`limits=Limits(max_connections=100)`，`timeout=httpx.Timeout(connect=5, read=REQUEST_TIMEOUT_MS/1000)`。
3. SSE：`StreamingResponse(media_type="text/event-stream")`，生成器内 `try/finally` 确保上游连接关闭 + 日志落库。
4. 判定器独立超时 3s：`asyncio.wait_for(decider.decide(ctx), timeout=3)`，超时视为 L2 未命中进入 L3。

## 七、日志与 Trace

- `observability/trace.py`：`contextvars.ContextVar("trace_id")`；中间件为每请求生成 `uuid4().hex[:16]`（试跑台前缀 `preview-`）。
- 结构化 JSON 日志一行一事件：`{"ts","level","trace_id","event","layer","model","latency_ms"}`。
- **API Key / 厂商密钥永不入日志**；input_text 记录前做长度截断 + 可选脱敏。

## 八、异常处理与降级矩阵

| 故障 | 捕获位置 | 行为 | fallback_reason |
|---|---|---|---|
| 判定器超时/异常 | pipeline | 跳过 L2 进 L3 | `DECIDER_UNAVAILABLE` |
| Jev confidence < T2(0.5) | l3_fallback | 走映射最优候选 | `LOW_CONFIDENCE` |
| 目标模型 429/超时/5xx | adapters | 按 priority 取下一候选，最多重试 2 轮 | `UPSTREAM_UNAVAILABLE:<model>` |
| 全部候选失败 | api/v1 | 返回 3002（这是兜底链耗尽，非首错） | 保留最后一条原因 |
| Redis 不可用 | services | 放行 + 不缓存 | - |

## 九、配置项（core/config.py，pydantic-settings）

```python
class Settings(BaseSettings):
    database_url: str = "sqlite:///./llmbridge.db"
    redis_url: str | None = None            # 空 = 不启用缓存
    jwt_secret: str
    jwt_expire_seconds: int = 86400
    encryption_master_key: str              # AES 主密钥，环境变量注入，严禁入库
    judge_provider: str = "jev"             # jev / mock
    jev_api_key: str | None = None
    jev_base_url: str = "https://api.typesafe.ai/v1/systemone"
    route_confidence_threshold_t2: float = 0.5
    default_model_id: int = 1
    request_timeout_ms: int = 30000
    decider_timeout_ms: int = 3000
    route_cache_ttl: int = 3600
    log_batch_size: int = 50
```

`.env.example` 提供全字段注释模板；`encryption_master_key` 与 `jwt_secret` 在生产必须由部署环境注入。

## 十、测试策略

- 单测：三层路由分支（L1 命中/未命中、L2 合法/超时/低置信、L3 兜底/降级）、crypto 往返、quota_cache 降级路径。目标：路由模块行覆盖 ≥90%，全局 ≥80%（基线门禁）。
- 契约测试：`BaseDecider` 同一组用例跑 JevDecider（mock httpx）与 MockDecider，断言输出同构。
- 集成：httpx `AsyncClient(app=...)` 全链路——建规则→/v1 调用→断言 5 个 `x-router-*` 头。
