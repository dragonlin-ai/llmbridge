## 四、Axios 封装（request.ts）

```
请求拦截：注入 Authorization: Bearer <token>；统一 trace 头 x-client-trace-id
响应拦截：HTTP 401 → 清 token 跳 /login
         body.code !== 0 → ElMessage.error(message) 并 reject
         body.code === 0 → 直接返回 data 字段
```

分页请求统一走 `PageParams{page,page_size,order_by,order}`，响应 `PageResult<T>{total,items}`。

## 五、SSE 处理（api/sse.ts）

控制台的「模型连通性/试跑对比调试」需要流式观感。约定：

1. 只用 `fetch` + `ReadableStream` 手写解析（EventSource 不支持自定义 header）。
2. 响应头里读 `x-router-*` 5 字段并**先于首分片渲染**判定信息（与后端「首 token 前决策完成」呼应）。
3. 断线不自动重连（调试场景重连会造成重复调用计费），显示「已断开」状态条。

## 六、关键业务组件契约

### RouteChainBar（链路可视化条）

| Prop | 类型 | 说明 |
|---|---|---|
| hitLayer | `'L1'\|'L2'\|'L3'` | 命中层 |
| details | `{layer, status:'hit'\|'skipped'\|'failed', reason?, latencyMs?}[]` | 每段状态 |

配色（与 UI 说明书一致）：L1 `#67C23A` / L2 `#7F77DD`（Jev）/ L3 `#F56C6C`（兜底）；跳过段灰显，hover 显示跳过原因。三段宽度相等，命中段填充、其余描边。

### ProbChart（Jev 概率分布）

| Prop | 类型 |
|---|---|
| probabilities | `Record<string, number>` |

横向条形图，按概率降序；**T2 阈值线**（0.5，可配）以虚线叠加——低于阈值的整体在 RouteChainBar 上表现为 L3 兜底，这是把「为什么兜底」可视化的关键。

### ConditionEditor（条件编辑器）

双向：可视化行编辑（field 下拉 + op 下拉联动 + value 输入）↔ JSON 文本框；切换时互相校验（regex 试编译、op 越界报错）；对外 `v-model:condition` 输出符合接口说明书 §3.4 Schema 的对象。

### TraceTimeline

纵向时间轴：请求进入 → L1/L2/L3（含耗时与跳过原因）→ 上游调用 → 响应下发；降级事件插入红色节点显示 `fallback_reason`。

## 七、Pinia Store 设计

| store | state | 核心 action |
|---|---|---|
| user | token/role/username | login() logout()；token 持久化 localStorage |
| models | providers[] models[] | fetchAll() testProvider(id) toggleModel() |
| rules | rules[] | fetch() save() reorder(ordered_ids) |
| logs | filters list traceDetail | fetch() fetchTrace(trace_id) |

## 八、编码规范

- 组件名多单词 PascalCase；composable `use*`；类型与后端字段**逐字对齐**（snake_case 不转驼峰，减少心智映射）。
- 所有金额展示 `¥` + 千分位（utils/format.ts 唯一出口）。
- API 层禁止出现组件级逻辑；组件不得直接 import axios。

## 九、构建与代理

`vite.config.ts`：`server.proxy = { '/v1': 'http://localhost:8000', '/admin': 'http://localhost:8000' }`；构建产物 `dist/` 交 Nginx 静态托管。
