## 二、关键技术要点

### 2.1 判定优先级链（pipeline 编排）

```
请求 → 归一化文本 → 查缓存(命中即返回)
     → L1 规则（sync，遍历 enabled 规则按 priority 升序）
     → L2 decider.decide()（wait_for 3s 超时；异常/低置信→L3）
     → L3 映射：task_type→capabilities 匹配→权重评分→取最高分
     → 全链失败 → DEFAULT_MODEL_ID（fallback_reason=FINAL_FALLBACK）
```

### 2.2 Decision 契约（deciders/base.py）

`Decision(task_type, confidence, probabilities, features, decider)`——Jev 与 Mock 输出**同构**，共用同一组契约测试。Jev 取值路径：`answers.task_type.choice/.probabilities/.confidence`；`features` 由 complexity(Score)+has_code/is_sensitive(Noul) 组装。

**实测口径（jev-1.13.0，2026-09-21）**：`complexity` 是 score 类型，官方返回的是 **0~2 的类别期望值**（`legend = {0:简单, 1:中等, 2:复杂}`，`score = Σ(类别索引 × 概率)`），入 `features` 前必须 `/2` 归一化到 **0~1**，才能与 MockDecider 的口径一致；`has_code` / `is_sensitive` 取 `.noul`（同样 0~1）。**注意 0.0 是合法取值，数值字段不得用 `or` 兜底**（曾因此把 `score=0.0` 误判为缺失，见 D-13）。

### 2.3 降级矩阵（全部落 request_log.fallback_reason）

`DECIDER_UNAVAILABLE` / `LOW_CONFIDENCE` / `UPSTREAM_UNAVAILABLE:<model>` / `FINAL_FALLBACK`。上游失败重试：同 provider 不重试，直接按 priority 取下一候选，最多 2 轮。

### 2.4 SSE

异步生成器三段式：`yield 判定元信息前`必须完成 pipeline；上游 chunk 逐段转发 OpenAI 兼容格式；`finally` 关闭上游连接 + 批量队列落日志。

### 2.5 x-router-* 响应头

非流式：`JSONResponse` 后 `response.headers` 补 5 字段；流式：`StreamingResponse` 的 `headers` 参数在启动时注入（首包前生效）。

## 三、核心模块实现指引

### 3.1 router_engine/pipeline.py

```python
async def route(ctx: RouterContext, decider: BaseDecider, rules: list[RouteRule]) -> RouterContext:
    # 缓存 → L1 → L2 → L3，任一命中即短路返回
    if (hit := await l1_rule.match(rules, ctx)) is not None:
        ctx.hit_layer, ctx.final_model = "L1", hit.model
        return ctx
    decision = None
    try:
        decision = await asyncio.wait_for(decider.decide(ctx), settings.decider_timeout_ms / 1000)
    except (TimeoutError, Exception):
        ctx.fallback_reason = "DECIDER_UNAVAILABLE"
    if decision and decision.confidence >= settings.route_confidence_threshold_t2:
        ctx.hit_layer, ctx.decision = "L2", decision
        ctx.final_model = l3_fallback.pick(decision.task_type, ctx.candidates)
        return ctx
    if decision:
        ctx.fallback_reason = "LOW_CONFIDENCE"
    ctx.hit_layer = "L3"
    ctx.decision = decision                      # 可能为 None
    ctx.final_model = l3_fallback.pick_default(ctx.candidates)
    return ctx
```

注意：L1 命中 `confidence=1.0` 且响应头**不带** `x-router-task-type`。

### 3.2 deciders/mock_decider.py

无外部依赖的确定性判定：按关键词表给 task_type 打分生成概率分布（softmax 归一），confidence=最高概率。**单测与离线开发全靠它**——不配 JEV_API_KEY 时自动启用。

### 3.3 api/v1/chat.py

流程：鉴权（Bearer）→ 限流（quota_cache）→ 组 ctx（token_len=字符数/2.5）→ `pipeline.route` → 5 响应头 → 非流式一次性返回 / 流式 StreamingResponse。异常兜底：最外层 except 返回 OpenAI 错误格式，**绝不 500 裸栈**。

### 3.4 api/admin/route_preview.py

复用同一 `pipeline.route`，唯一差异：不写 request_log、不调上游、trace_id 前缀 `preview-`。响应体按接口说明书 §3.8 全字段组装（含 candidates 打分排序）。

### 3.5 services/quota_cache.py

每个方法入口 `if not self._ok: return 放行默认值`——Redis 异常只 WARN 一次（防日志风暴），后续静默降级。

### 3.6 data/provider_catalog.py（内置厂商目录，V1.4 新增）

**只读常量模块**：不连库、无副作用，可被脚本、测试、接口层直接 import 做对照。
`CATALOG_VERSION="2026-09"`、`PRICE_DISCLAIMER`、`CatalogProvider` / `CatalogModel` dataclass、`CATALOG` 元组、
`build_remark(p)`（拼「密钥申请入口 + 接入注意事项」）、`find_catalog_provider(name)`。

收录 12 家国内主流厂商 + 27 个代表模型（DeepSeek / 阿里云百炼 / 智谱 GLM / 月之暗面 Kimi / 火山方舟 /
百度千帆 / 腾讯混元 / MiniMax / 零一万物 / 阶跃星辰 / 百川智能 / 硅基流动）。
价格为**元/百万 token 参考价**，文件头标注三类失真来源：时间漂移 / 平台差异 / 计费口径差异；
逐条模型带 `price_note`。**缺失价格写 `None` 而不是 0** —— 0 会让成本因子在 `score_candidates()` 里霸占排序。

### 3.7 services/provider_access.py（接入态判定，V1.4 新增）

**「是否已接入」的唯一判据是密钥能否解密**，不引入 `is_configured` 字段：

| 函数 | 语义 |
|---|---|
| `has_usable_key(encrypted)` | 能否 AES-256-GCM 解密且明文非空白。占位密文 `ENC_PLACEHOLDER_<name>` 非法 → 抛 `ValueError` → False |
| `is_provider_usable(provider)` | 密钥可用 **且** `provider.enabled` |
| `provider_unavailable_reason(provider)` | 归因文案。**顺序必须是「先密钥后启用」**——反了会把「厂商未填密钥」报成「模型已停用」，把使用者指错方向（缺陷 D-28） |

配套 `api/deps.py: load_routable_models(session)`：JOIN Provider，过滤
`Model.enabled AND Provider.enabled AND has_usable_key`，是 `/v1` 与试跑台**共用**的候选池加载入口。
试跑台 `pool` 三项统计（`disabled_models` / `blocked_by_provider` / `routable`）须**互斥且自洽**，
统计口径同样「先看厂商后看模型」。

### 3.8 厂商目录预置（幂等）

**实现在包内** `app/data/catalog_seed.py`（`seed_catalog()`）；`app/services/bootstrap.py`
在服务启动时调用它完成首次引导。`scripts/seed_provider_catalog.py` 已退化为**薄壳 CLI**
（只做参数解析与报告落盘），`llmbridge-catalog` 与启动引导走的是同一份实现。

匹配顺序：先按 `name`，未命中按「同厂商 + 同接入形态（目录内唯一）」，最后回退 `base_url`
（仅当它在目录内唯一 —— MiniMax 按量与 Token Plan 共用端点，不判唯一会认错通道）。
新通道一律 `enabled=False` + 占位密文；`--dry-run` 预演，`--overwrite` 覆盖已有值，
`--prune-orphans` 清理目录残留行（三重条件同时满足才删）。
厂商 `remark` 由 `build_remark()` 生成；模型 `capabilities` **必须 `json.dumps`**（见 K-06）。

默认**只铺接入通道**（`with_models=False`）。

## 五、构建与运行

```bash
# 数据库（PostgreSQL）
createdb llmbridge            # 或 SQL: CREATE DATABASE llmbridge ENCODING 'UTF8';
# .env 配 DATABASE_URL=postgresql+psycopg://<用户>:<密码>@<主机>:5432/llmbridge
#   密码含 @ : / 等特殊字符须 URL 编码（@ → %40）
# 从旧 SQLite 库全量迁移（可选，幂等）：python scripts/migrate_sqlite_to_pg.py

# 后端
python -m venv .venv && .venv\Scripts\activate      # Windows
pip install -e ".[dev]"
copy .env.example .env                              # 填 DATABASE_URL / jwt_secret / encryption_master_key
python -m app.seed                                  # 建表 + 默认管理员 + 评测样本 + 厂商接入目录（幂等）
                                                    # 其实可省：服务启动引导会自动做同样的事（AUTO_BOOTSTRAP）

# 内置厂商目录预置：13 家主流厂商 / 24 条接入通道（均 enabled=False，待填 Key）
#   默认只铺接入通道，模型池留空待手工添加；加 --with-models 才连目录参考模型一起灌
python scripts/migrate_add_provider_remark.py       # 幂等补 provider.remark 列（新库建表已含则 skip）
llmbridge-catalog --dry-run                         # 预演，只打印不落库
llmbridge-catalog                                   # 实际写入（可重复执行，结果一致）
#   ↑ 等价写法：python scripts/seed_provider_catalog.py [--with-models]

uvicorn app.main:app --port 8000 --loop app.core.eventloop:selector_loop_factory

# 前端
cd admin-web && npm ci && npm run dev               # 5173，代理已指向 8000
```

> ⚠️ **`--loop app.core.eventloop:selector_loop_factory` 不可省略。**
> Windows 默认的 `ProactorEventLoop` 会让 psycopg3 在首次查询时抛
> `InterfaceError: Psycopg cannot use the 'ProactorEventLoop' to run in async mode`，
> 症状是「服务正常启动、但一登录就 500」。
> 带 `--reload` 时 uvicorn 走子进程模式会自己用 Selector，**不带 reload 的启动必须显式指定**。
> 启动日志会打印 `event_loop=... psycopg_compatible=True/False` 与 `db connectivity=ok/FAILED`，
> 据此判定是否配置正确（详见 `03-端到端联调验证记录.md` §七）。

## 六、已知问题（编码前预判，非实际发生）

| # | 预判 | 验证状态 |
|---|---|---|
| K-01 | Jev 官方 API 国内不可达，联调只能靠 MockDecider + 契约测试模拟响应 | **已推翻**（2026-09-21 实测）：本机直连 `https://api.typesafe.ai/v1/systemone` 返回 **HTTP 200**（`model=jev-1.13.0`，延迟 0.4~1.2s），L2 真实判定路径已实测（53/53，见 `03-端到端联调验证记录.md` §4.4）。**但数据出境合规问题与预判无关、依然存在**，见该文档 U-02 |
| K-02 | SQLite 多 worker 写锁——开发期 uvicorn --reload 单进程可避，压测须 PG | **前提已消失**（2026-09-22）：开发与生产统一为 PostgreSQL，SQLite 不再参与压测。新增的 Windows 侧约束见 K-05 |
| K-03 | token_len 估算（字符数/2.5）对中文偏差大，token_len 类规则阈值需按中英比例调 | 待填（阶段四验证） |
| K-04 | SSE 经 Vite 代理可能被缓冲——需 vite proxy 配 `configure` 关 buffering | 待填（开发中验证） |
| K-05 | **Windows + PostgreSQL 的事件循环约束**：psycopg3 拒绝 ProactorEventLoop，uvicorn 在不带 `--reload` 时恰好选它 → 启动成功但一访问数据库即 500 | **已实际发生并已修复**（2026-09-22）：新增 `app/core/eventloop.py`，启动需带 `--loop app.core.eventloop:selector_loop_factory`；同时在 `app/main.py` 加了启动自检，配错时打 ERROR 并做一次真实探活。详见 `03-端到端联调验证记录.md` §七 |
| K-06 | **psycopg 不做方言转换**：`model.capabilities` 是 Text 列，若直接写入 Python `list`，psycopg 会按 PG 原生数组适配成字面量 `{general,code_generation}`，而非 JSON 字符串 → 下游 `json.loads` 必崩 | **已实际发生并已修复**（2026-09-21，缺陷 D-26）：预置脚本显式 `json.dumps(list(...), ensure_ascii=False)`；并加了一条「非法 JSON 行数 = 0」的库内断言。同类风险适用于所有「声明为 Text 但语义是 JSON」的列 |
| K-07 | **D-25 类隐患**：预置大量「未填 Key」厂商后，若候选池只看 `Model.enabled`，会选中必然调用失败的模型 → 降级链随机 502 | **已实际发生并已修复**（2026-09-21，缺陷 D-25）：新增 `load_routable_models()` 统一候选池口径，`/v1` 与试跑台共用。**这是预置功能的核心风险，新增任何「批量预置」都要先确认候选池口径未被绕过** |
